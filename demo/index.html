The problem

Agents already work with real keys.

FelonyBench has tracked 13 incidents since July where frontier-lab agents affected third parties. Several are actions any coding agent could take with the credentials on your laptop.

It happened to me too. An audit of my own coding agents found one had turned off approval prompts, and others merged to production. Prompts ask agents to behave. They don't guarantee it.

Live on Flower SuperGrid

One agent's catch protects all four.

Four agents run on their own SuperNodes, on three model providers. Only Backend knows customer exports are off-limits. Watch what happens when one of them is attacked.

Ready. Only Backend guards customer data. 

  

  
The attack runs only on machines whose operator turned it on, so a prompt alone can't trigger it. QA runs Kimi-K2.7-Code and Release runs MiniMax-M3 on Nebius Token Factory. Backend and iOS run GPT.






  How it works
  
Four steps, all in code.

  

    
CheckEvery tool call is checked before it runs. The model never gets a vote.0.03 ms median

    
WidenA block becomes the broadest rule that still allows normal work.no false alarms on normal work

    
ShareThe rule travels through the Flower coordinator. Nothing else does.rule only, rate-limited

    
ValidateEach agent tests the rule on its own work before using it.bad rules rejected

  Available now
  
Works with the agents you already use.

  
Built into Flower Agents, with hooks for Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI and Grok. Rules come in packs, like skills: secrets, git safety, publishing and customer data. Set up a project with warden.py init, and review what the fleet learned with warden.py review.

  
    
    
  • Rules can be phrased around. Wagent is a layer on top of sandboxes, not a replacement.
    • 
    
  • Shared rules are validated and rate-limited; signing is built on a branch.
    • 
    
  • "Ask" actions are held on Flower today; approval cards are next.
